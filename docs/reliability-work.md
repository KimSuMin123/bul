# LMS 안정화 작업

브랜치: `fix/lms-state-and-save-reliability`

## 구현 범위

- 표준 Supabase Auth 세션을 사용하고 서버에서 현재 사용자와 관리자 역할을 검증한다. 브라우저에 저장된 프로필은 인증 근거로 사용하지 않는다. 로그인·갱신·로그아웃의 지연 응답이 새 세션을 덮거나 만료시키지 않도록 보호한다.
- 계정 변경 시 개인 데이터와 관리자 문제은행을 즉시 비운다. 이전 계정이나 이전 조회의 지연 응답은 반영하지 않는다. 성공한 빈 응답은 빈 목록으로 처리하며 조회 실패를 샘플 데이터로 대체하지 않는다.
- 신청·CMS·Q&A·회원관리·수납은 서버 확인 후 성공을 표시한다. 실패 시 입력을 보존하고 중복 제출을 방지한다. 강좌 정보와 시험 문제은행은 한 트랜잭션으로 저장한다.
- 수납은 서버 RPC와 요청 UUID를 사용한다. 응답 유실 후 재시도·새로고침에도 동일한 요청 UUID를 유지하여 이중 수납을 방지한다.
- 진도는 서버 시간과 실제 재생 위치의 변화로 계산한다. 같은 구간의 반복 시청을 중복 합산하지 않는다. 주기 저장과 마지막 저장을 순서대로 실행하며 실패 시 재시도를 제공한다.
- 문제은행 정답은 서버 비공개 스키마로 옮긴다. 시험 출제·채점·수료증 발급 자격 및 중복 발급은 서버 RPC로 검증한다.
- 영상은 비공개 Storage와 signed URL을 사용한다. 운영 업로드는 사용자 JWT로 직접 요청하며, FFmpeg 변환은 명시적으로 선택한 로컬 개발 환경에서만 제공한다.
- 확인 모달의 취소 버튼 Enter 동작, 포커스 순환·복귀와 관리자 로그인 직후 화면 이동을 보완한다.

## 검증 명령

```text
npm test
npm run test:browser
npm run test:e2e
npm run build
git diff --check
```

- `npm test`: 단위·API 실패 계약·인증 경합·UI 이벤트·미디어·Edge handler·실제 PostgreSQL(PGlite) 검증.
- `test:browser`: 실제 React Context·모달·플레이어를 브라우저에서 실행하고 지연 응답과 실패를 주입한다.
- `test:e2e`: 실제 앱 UI를 Playwright로 조작한다. 모든 Auth·DB·Storage 요청은 격리된 fixture에 연결하며 외부 통신을 차단한다. 실행 실패는 프로세스 실패로 전달한다.
- Playwright HTML 보고서: `test_artifacts/playwright/report/index.html`. 성공 화면·실패 trace 등은 `test_artifacts/playwright/results/`에 저장된다.
- 기존 `TEST_REPORT.md`는 2026-09-20의 과거 보고서다. 이번 변경의 검증 결과로 사용하지 않는다.

## 배포 상태와 검증 한계

운영 DB·Auth·Storage 정책은 아직 변경하지 않았다. 새 프론트엔드는 두 SQL 마이그레이션과 `lms-auth` Edge Function을 함께 배포해야 한다. 순서·중복 데이터 점검·환경 설정은 [인증·권한 전환 문서](security-migration.md)를 따른다.

제공된 테스트 계정으로 마이그레이션 전 기존 빌드의 로그인과 관리자 화면 접근만 읽기 전용으로 확인했다. 이는 새 인증 서버의 운영 검증이 아니다. 선택적 `scripts/smoke_live_login.mjs`는 환경변수로 테스트 자격증명을 받아 민감 정보를 파일에 기록하지 않는다.

로컬 검증은 Supabase Gateway·Auth·Storage의 실제 배포 연동을 대체하지 않는다. 운영 전 스테이징에서 기존 회원 이관, 실제 영상·긴 영상 재생, 신규 가입부터 수료증 발급까지 확인해야 한다. FFmpeg 실행은 모의 프로세스로 검증했다.
