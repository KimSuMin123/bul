# LMS SMS worker

Question notifications to the administrator include the question body, shortened only when necessary to keep the whole LMS message within a conservative 1900 UTF-8 byte budget, plus a full-question link. Answer notifications include a direct link without disclosing the answer body. Four transactional events: enrollment application -> student + administrator; new question -> administrator; new answer -> question author. SQL migration 003 enqueues jobs in the business transaction. Provider calls happen only in this worker. No browser SMS request is needed. A duplicate unchanged pending application is not another event. Reapplication after activation/expiry increments application_version; payment activation itself never sends an application message.

## Processing and recovery

`lms_claim_sms(p_limit)` is service-only, uses row locks/SKIP LOCKED, and issues a unique lease per job. The worker claims at most five jobs per invocation. `lms_finish_sms` requires that exact lease and records an attempt without message bodies or phone numbers. A lease-expired in-flight job becomes `uncertain`; it is never blindly reclaimed and sent again. Terminal mock/accepted jobs cannot be retried through the admin RPC.

HTTP 429 retries with exponential delay (60, 120, 240, 480 seconds) and a five-attempt cap. Definitive 4xx/provider rejection is failed. Timeouts, 5xx, malformed responses, and worker crashes can leave uncertain delivery; inspect SOLAPI logs before deciding. A lost database response after provider acceptance is also treated conservatively through lease expiry. Exact-once delivery cannot be guaranteed across a provider/network boundary without provider idempotency.

Admin RPCs (verified Auth role required): `lms_sms_audit({p_limit:50})` returns only job ID, kind, status, attempts, safe code, provider group ID and timestamps. `lms_retry_sms({p_id, p_confirm_not_sent:false})` retries failed jobs; an uncertain job additionally requires `p_confirm_not_sent:true` after the administrator verifies no send occurred at the provider. Neither RPC exposes private payloads. SQL operators can inspect `lms_private.sms_attempts` when needed. Private payloads contain recipient name/phone, course details and question content (question notifications only); apply an institution-approved retention period and restrict backup access. No retention period is invented by this implementation.

## Other API contracts

- register/admin-register require literal `privacyConsent:true` and `privacyPolicyVersion:'2026-09-23'`. Database stamps time; caller timestamps are ignored. `legacy_admin_backfill` is administrative provenance, not an assertion of actual historical consent. New registrations use `registration`; administrator attestation uses `admin_attested`.
- login accepts users.id or users.login_id, while Auth synthetic email is derived from the immutable canonical users.id. Private login_identifiers prevents cross-namespace alias collisions. No migration changes a live alias or password.
- `lms_can_watch_lecture(p_lecture_id)` gates both signed Storage access and progress writes on the immediately preceding ordered lecture having >=80% progress. Completion, examination and certificates remain governed by the 100% rules in migration 001.
- site_announcements public rows require enabled + current schedule. Administrator CRUD and announcement-images upload/delete require server-side admin identity. Public image files remain directly addressable after publication ends; do not put private material in this public bucket.
- Welcome audio defaults to the supplied master optimized as `public/audio/namo_buddhaya_song.mp3`, served from the same-origin `/audio/namo_buddhaya_song.mp3` path. `preload='none'` defers the MP3 request until an explicit play click. `VITE_NAMO_AUDIO_URL` overrides this source; without an override, `VITE_NAMO_AUDIO_SOURCE=cloud` optionally selects Supabase instead. In cloud mode the component requests only signed-URL metadata when it mounts, then waits for the play click before downloading audio. URL preparation is not audio preloading or autoplay.
- For optional cloud playback, the lectures bucket is private in production. Migration 003 permits anonymous/authenticated SELECT only for `audio/namo_buddhaya_song.mp3` with Storage MIME metadata `audio/mpeg`. Adjacent audio paths, differently cased filenames, other buckets, wrong MIME metadata and lecture videos do not gain public access. No upload/write permission is added and the service role policy is unchanged. After deployment, anonymous signing returned 200 and actual desktop/mobile Chrome playback advanced and paused within two seconds without media errors. The same live check confirmed an existing lecture video could be signed by the service role but not anonymously. Negative path/MIME policy cases are additionally covered by offline SQL tests.
